## فلسفة الخطة

**القاعدة الذهبية:** كل مرحلة يجب أن:
1. تُقلّل **المساحة** (سطح الكود + الـ complexity)
2. تُعزّز **الفائدة** (وضوح، أمان، أداء)
3. تحافظ على **التوافق العكسي** (لا كسر للنماذج أو الـ APIs في المراحل المبكرة)

**النمط العام:** Refactor **→** De-duplicate **→** Centralize **→** Document **→** Verify

## المبدأ الموحّد: القاعدة الذهبية للصقل

```
1. لا تغيّر API عام بدون فترة سماح
2. أي refactor يجب أن يحافظ على نفس الـ tests passing
3. لا تضيف dependency جديد بدون موافقة (افضل: استخدام ما هو متاح)
4. كل refactor = 1 commit صغير قابل للـ revert
5. كل مرحلة = PR واحد + Checklist صريح
```
